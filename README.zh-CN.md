# Twinfold

**备份真的复制完整了吗？把两个文件夹放进来，核对一下。**

一个可以离线打开的小网页：按内容核验文件，找出缺失、变化、新增和移动。无需上传、注册或安装桌面软件。

[在线使用](https://utokyo2026.github.io/twinfold/) · [下载离线网页](https://github.com/UTokyo2026/twinfold/releases/latest) · [English](README.md)

![Twinfold 文件夹核验演示](docs/demo.png)

## 使用

构建需要 Node.js 20.19 或更新版本。构建完成后的网页不需要 Node.js。

```sh
npm ci
npm run build
```

双击打开 `dist/index.html`。先点“试用演示”，就能体验完整流程。

也可以运行 `npm start`，打开 <http://127.0.0.1:4178>。

1. 在 A 侧选择原始文件夹，B 侧选择备份或较新版本。
2. 点击“比较文件夹”，等待内容核验完成。
3. 查看缺失、变化、新增和移动的文件。可以搜索、筛选或导出 CSV 报告。
4. 保存快照；日后载入快照，再与新的文件夹核对。

## 适合什么场景

- 把照片、论文或项目复制到 U 盘后，确认有没有漏文件。
- 整理文件目录后，区分“只是换了位置”和“内容已经改变”。
- 保存一份文件清单，日后检查新备份是否与当时的记录一致。

## 特点

- **比对内容**：使用 SHA-256；同名、同大小并不自动视为相同。
- **保守识别移动**：只有唯一的同内容匹配才标记为移动或改名，重复内容不会随意配对。
- **离线单文件**：页面、样式和哈希实现一起打包在一个 HTML 文件中，没有远程依赖。
- **分块读取**：每次读取 4 MiB，不会把整个大视频一次读进内存。
- **只读操作**：不会修改、同步、移动或删除原始文件。
- **快照和报告**：保存相对路径、大小和哈希，不保存文件正文。
- **中英文界面**：可手动切换。

## 边界说明

检查范围是浏览器列出的文件内容及区分大小写的相对路径，不包括空目录、权限、时间戳或符号链接本身。云端占位文件、隐藏文件和系统文件的可见性取决于浏览器与操作系统。核验期间请保持文件不变。

无法读取的文件会明确显示“未能核验”，对应侧不允许导出不完整快照。快照是未签名的历史记录，不能证明备份的时间、存储位置或当前仍然存在。快照和报告包含文件名，分享前请留意。

读取文件时采用固定大小的分块；文件列表和结果仍会随文件数量占用内存。尚未对 TB 级档案或百万文件做性能验证。导入快照上限为 40 MiB / 100,000 条记录。

已在桌面 Chromium 中验证真实文件夹、导出与快照回读。其他浏览器的目录选择支持可能不同。手机可查看界面和演示，实际文件夹核验建议在电脑完成。

如果使用网站版本，网站主机仍会收到普通访问请求及 IP 等信息。下载 HTML 并断网打开，可以完全离线使用。

## 开发与开源

```sh
npm test
npm run build
npm start
```

MIT 协议。哈希实现使用 `@noble/hashes`，相关许可证随仓库和离线网页附带。

文件夹对比已有成熟同类工具；Twinfold 的目标是把日常备份核验做得简单、直观、容易携带。完整实现说明与限制见 [English README](README.md)。
